# Context Reader — минимальная дизайн-система

Этот документ фиксирует общий визуальный язык, который уже используется в Reader
и тренировке. Это не требование одномоментно переписать все старые экраны.

## Принципы

- Интерфейс спокойный: текст и контекст важнее декоративных элементов.
- Основное действие на экране одно; вторичные действия визуально тише.
- Интерактивные элементы имеют видимый hover/focus и область нажатия 44 px.
- Цвет не является единственным сигналом состояния: результат всегда содержит
  текстовый статус.
- Article-шрифт используется для изучаемого языка и текста; UI-шрифт — для
  навигации, подписей и контролов.

## Токены

Источник истины — `src/styles/tokens.css`.

- Цвета: `--bg`, `--surface`, `--surface-2`, `--ink*`, `--border*`,
  `--accent*`.
- Семантика: `--success-*`, `--warning-*`, `--error-*`. Для каждого состояния
  есть foreground, soft background и border в light/dark темах.
- Шаги: `--space-1`…`--space-6` = 4…24 px.
- Радиусы: `--radius-control` для полей/кнопок, `--radius-panel` для панелей.
- Высоты: `--control-height-md` 44 px, `--control-height-lg` 52 px,
  `--touch-target` 44 px.
- Focus: `--focus-ring`; использовать только через `:focus-visible`.

Новый компонент не должен вводить собственный accent или семантический цвет,
если нужное значение уже выражается токеном.

## Компоненты

Реализация находится в `src/components/ui/controls.tsx`, иконки — в
`src/components/ui/icons.tsx`, стили — в `src/styles/ui.css`.

### Button

Варианты:

- `primary` — главное действие (`Дальше`, `Проверить`);
- `secondary` — альтернативное действие (`Попробовать ещё раз`, голос);
- `ghost` — обратимое или низкоприоритетное действие (`Подсказка`, пропуск).

Размер `lg` применяется к основным действиям формы. Для двух равноправных
контролов используется одна строка 50/50 даже на ширине 320 px.

### IconButton и SpeakerButton

`IconButton` всегда получает доступное имя через `label`. `SpeakerButton` —
единая кнопка озвучки для Reader, подсказки, объяснения соседнего слова и
правильного ответа. Emoji вместо общей SVG-иконки не используются.

### TextInput

Обычное поле имеет границу со всех сторон, фон, radius и focus-state.
`autoSize` использует невидимый mirror с той же типографикой и растёт по
содержимому до ширины контейнера. На узком экране поле может перейти на следующую
строку, но не выходит за карточку.

### FeedbackPanel

Тоны:

- `success` — `Верно`;
- `warning` — `Почти`;
- `error` — `Не совсем`;
- `neutral` — ответ был раскрыт подсказкой или оставлен пустым.

Панель объясняет результат, но не содержит весь экран ответа. Сравнение `Твой
ответ` / `Правильно` и озвучка правильной формы идут в соседней result-зоне.

## Состояния и доступность

- `disabled` не должен быть единственным объяснением недоступности: для
  микрофона используется `title` или текст ошибки рядом.
- Асинхронная загрузка получает `role="status"`/`aria-live` там, где её должен
  заметить пользователь.
- Иконки внутри подписанной кнопки имеют `aria-hidden`.
- Соседние слова в тренировке — настоящие `<button>` с hover/focus и понятным
  `title`, а не кликабельные `<span>`.
- Skeleton не показывает временный контент, который затем заменится.

## Область применения

Сейчас общие компоненты обязательны для новых элементов тренировки и для
озвучки Reader. Остальные экраны мигрируются только при их следующей предметной
доработке, чтобы не смешивать массовый визуальный рефакторинг с продуктовой
логикой.
