# Раздел «Учить» — план редизайна (2026-07-29)

Спроектировано после живого использования первой версии тренировки: очередь
кончается — и делать нечего, список слов ничего не говорит о прогрессе, после
сессии нет итогов. Решения согласованы с пользователем: **статистика без
геймификации** (никаких стриков/XP), **статусы + даты** (без Anki-терминов
вроде ease factor), выход — этот план + HTML-мокапы `05`–`07`.

## Что взяли из других приложений (и что отвергли)

| Приложение | Что берём | Что не берём |
| --- | --- | --- |
| Anki | Триада статусов (new / young / mature → «Новое / Учу / Знаю»), порог зрелости «интервал ≥ 21 дня», состояние «колода пуста» с осмысленными действиями, флаг сложных слов (leech) по числу ошибок | Терминологию SRS в UI, ручную настройку ease, «review ahead» с пересчётом интервалов |
| Duolingo | Экран итогов после каждой сессии, «повторить ошибки» | Стрики, XP, маскоты, скрытие прогресса |
| Memrise | Раздельные входы «учить новые» и «повторять» при пустой очереди | Метафору цветка, спид-ревью |
| Quizlet / LinguaLeo | Фильтры списка по статусу, карточка слова с действиями | Наборы/сеты — у нас слова живут одним пулом на язык |

## Статусы слова

Считаются из уже существующего `ReviewState` — **миграция данных не нужна**:

| Статус | Условие | Цвет |
| --- | --- | --- |
| Новое | ещё ни одной тренировки (`repetitions === 0 && lapses === 0`) | accent (фиолетовый) |
| Учу | тренировалось, `intervalDays < 21` | warning (янтарный) |
| Знаю | `intervalDays >= 21` (порог Anki mature) | success (зелёный) |

Дополнительный бейдж **«сложное»** при `lapses >= 4` (аналог Anki leech) —
не отдельный статус, а пометка поверх «Учу»: слово, которое стабильно не
запоминается, кандидат на сброс прогресса или удаление.

«Знаю» — не терминальное состояние: ошибка в повторе возвращает слово в «Учу»
(SM-2 уже так делает через сброс `repetitions`/`intervalDays`).

## Экраны

### 1. Хаб «Учить» (мокап `05-learn-hub.html`)

Замена текущего `LearnPage`. Сверху вниз:

- **Карточка дня** — два состояния:
  - Очередь не пуста: «N на сегодня» (с разбивкой «из них новых: X») +
    primary «Начать».
  - Очередь пуста: «На сегодня всё ✓», строка «ближайший повтор — завтра,
    5 слов», и два secondary-действия:
    - **«+5 новых слов»** — видна только если есть нетронутые новые слова;
      запускает полноценную SRS-сессию из следующих новых (это настоящие
      первые знакомства, расписание пишется — так же делает Anki custom study).
      Технически это тот же механизм отфильтрованной тренировки: фильтр
      «Новые» + порция 5;
    - **«Повторить без расписания»** — free practice по всем словам
      (уже реализовано, SRS не трогается).
- **Чипы-фильтры со счётчиками**: `Все (9) · Новые (2) · Учу (5) · Знаю (2)` —
  фильтруют список ниже. И фильтр, и первичная сводка прогресса одновременно.
- **«Тренировать (N)» рядом с активным чипом** — когда выбран любой чип, кроме
  «Все», появляется действие «Тренировать (N)»: сессия ровно из отфильтрованных
  слов. Правило SRS остаётся единым и пословным: расписание обновляется **только
  для слов, которые реально к повтору** на момент ответа, остальные идут как
  учебные и расписание не меняют. Новых понятий это не вводит — «Повторить без
  расписания» это тот же механизм в случае, когда к повтору нет ничего. Итоги
  сессии сообщают честно: «Расписание обновлено для N слов из M».
  Для чипа «Новые» это полноценное первое изучение: у всех новых слов
  `dueAt` — момент сохранения, то есть в прошлом, поэтому все они к повтору и
  расписание пишется целиком. Отсюда важное следствие: кнопка **«+5 новых слов»**
  на пустой очереди — не отдельная механика, а частный случай того же
  механизма (фильтр «Новые», порция 5).
- **Список слов**: строка = слово + перевод слева, статусная точка + дата
  справа («сегодня», «завтра», «через 5 дн.»; для «Знаю» — просто дата).
  Сортировка: по ближайшему `dueAt` (due сверху). Тап по строке → карточка
  слова (экран 2). Текущий список вообще не реагирует на тап — это главная
  причина, почему раздел ощущается «слепым».

Много слов (50+): фильтры решают основную навигацию; поиск по слову —
отложен до реальной потребности (отмечен как v2).

### 2. Карточка слова — bottom sheet (мокап `06-word-card.html`)

**Принятое решение: это не новый компонент, а переиспользование
`ExplanationSheet`** из ридера (`src/components/ExplanationSheet.tsx`). Верхняя
часть карточки — ровно тот же разбор, который пользователь видел при чтении:
часть речи, крупная форма слова с озвучкой, перевод, строка-подсказка, блок
«В контексте», и «Подробнее» с таблицами форм. Ниже добавляется специфичная для
«Учить» часть: статус, прогресс и действия.

Почему это возможно без загрузки урока: `SavedWord`
(`src/content-system/savedWord.ts`) уже хранит почти весь `AnnotationSummary` —
`surfaceForm` → `displayForm`, `partOfSpeech`, `translation`, `audioText`,
`contextSource`/`contextTranslation` → `context.source`/`context.translation`,
`relatedSource`/`relatedTranslation` → `context.relatedSource`/
`context.relatedTranslation`. Значит `Annotation` для шита собирается прямо из
сохранённого слова.

Тир 2 («Подробнее») тоже работает: `fetchAnnotationDetails` принимает
`{ tokenId, sentence }`, где `sentence` — токенизированное предложение;
`contextSource` токенизируется локально через `tokenizeParagraphs` — ровно так,
как это уже делает `TrainingPracticeView.handleTapWord` для соседних слов.

Нужны две небольшие развязки в `ExplanationSheet`:

- проп `onContinue` («Продолжить отсюда» имеет смысл только в ридере) становится
  необязательным;
- строка действий делается подключаемой, чтобы «Учить» передал свой набор
  (Тренировать сейчас / Сбросить прогресс / Удалить слово) вместо
  «Сохранить + Продолжить отсюда».

Выгода: пользователь видит для сохранённого слова ровно тот же разбор, что и в
чтении, — без второй реализации и без расхождения двух представлений одного и
того же.

Специфичная для «Учить» часть под разбором:

- Статусная строка: бейдж («Учу», при `lapses >= 4` ещё «сложное») +
  «следующий повтор — завтра».
- Прогресс словами, не цифрами SRS: «3 верных повтора подряд · 1 ошибка».
- Действия:
  - **«Тренировать сейчас»** — primary. Если слово не due, под кнопкой
    подпись «вне расписания — прогресс не изменится» и сессия идёт как
    free practice; если due — обычная тренировка со записью SRS.
  - **«Сбросить прогресс»** — слово снова «Новое» (для сложных слов,
    которые «прокликали» до высокого интервала, не выучив). С подтверждением.
  - **«Удалить слово»** — danger, с подтверждением.

**Открытый вопрос: слот-подсказка.** `SavedWord` не хранит поле `hint`
(`AnnotationHint` — label/source/translation), поэтому у уже сохранённых слов
строка-подсказка в шите будет отсутствовать. Два варианта: принять этот пробел
(шит и так рисует `hint` условно) либо начать сохранять `hint` в момент
сохранения слова — но это поможет только словам, сохранённым после изменения.
Решения пока нет.

### 3. Итоги сессии (мокап `07-session-summary.html`)

Показывается после последней карточки вместо молчаливого выхода в хаб:

- Заголовок «Сессия завершена» + крупно «6 из 9 верно» с разбивкой
  `✓ 6 · ≈ 1 · ✕ 2` в цветах вердиктов.
- Список слов сессии: слово + иконка вердикта; у слов, сменивших статус,
  подпись перехода («→ Знаю») — спокойное признание прогресса без фанфар.
  Тап по слову → карточка слова.
- Кнопки: **«Повторить ошибки (3)»** — учебная мини-сессия только из слов
  с `≈`/`✕`, расписание не трогает (первая попытка уже засчитана — тот же
  принцип, что у «Попробовать ещё раз» внутри карточки); **«Готово»** — в хаб.
- Вариант для free practice: тот же экран с бейджем «Вне расписания —
  прогресс не менялся».

Данные для экрана — вердикты по ходу сессии в памяти `TrainingPracticeView`,
ничего нового в Blob писать не нужно.

## Пользовательские пути

1. **Ежедневный**: хаб → «Начать» → сессия → итоги → (повторить ошибки) → хаб.
2. **«Хочу ещё»**: пустая очередь → «+5 новых» (реальный SRS) или «Повторить
   без расписания» (учебная) → итоги с соответствующей пометкой.
3. **Разбор слова**: чип «Учу» → тап по слову → карточка → тренировать /
   сбросить / удалить.
4. **Из чтения**: сохранил слово в Reader → оно «Новое», `dueAt = сейчас` →
   уже в сегодняшней очереди (как и сейчас).

## Механики и настройки

- **Дневной лимит новых слов** — настройка «Новых слов за сессию: 5 / 10 / 20»
  в существующем `SettingsOverlay` (рядом с «Фраза для тренировки»).
  Хранится в `AppPreferences` (опциональное поле, дефолт 10 — совместимо со
  старыми данными). `selectPracticeQueue` уже принимает лимит параметром.
- **«+5 новых»** — фиксированная порция, не настройка: жест «хочу ещё чуть»,
  а не смена дневной нормы.
- **Отклонено: досрочные повторы** («review ahead» — взять завтрашние слова
  сегодня с пересчётом SM-2). Портит интервалы ради сиюминутного «ещё», а
  потребность полностью закрывает free practice. Вернуться, только если
  free practice окажется недостаточно.

## Этапы реализации (каждый шипается отдельно)

- **A. Статусы + хаб**: чистая функция `wordStatus()` в `srs.ts` (+ тесты),
  редизайн `LearnPage` — карточка дня с двумя состояниями, чипы, список со
  статусами/датами и сортировкой. Сюда же — **«Тренировать (N)»** при активном
  чипе: действие живёт вплотную к чипам и не имеет собственного UI, а пословное
  правило SRS («расписание только для тех, кто к повтору») уже нужно этапу A,
  чтобы список честно показывал даты. В D его тащить незачем — там останется
  только порция «+5» как частный случай.
- **B. Итоги сессии**: сбор вердиктов в `TrainingPracticeView`, экран итогов,
  «Повторить ошибки», строка «Расписание обновлено для N слов из M».
- **C. Карточка слова**: переиспользование `ExplanationSheet` — две развязки
  (необязательный `onContinue`, подключаемая строка действий), сборка
  `Annotation` из `SavedWord` и локальная токенизация `contextSource` для тира 2.
  Плюс блок «Учить»: статус, прогресс, действия (тренировать одно слово /
  сбросить прогресс / удалить). Оценка сложности заметно ниже, чем у постройки
  карточки с нуля: вся вёрстка и стили разбора уже есть, писать нужно только
  адаптер данных и блок действий. Появилась зависимость от кода ридера — правки
  в `ExplanationSheet` теперь затрагивают два экрана.
- **D. Лимиты**: настройка дневного лимита новых + «+5 новых» на пустой очереди
  (поверх механизма отфильтрованной тренировки из A).

Зависимости: B и C не зависят друг от друга, оба опираются на A (статусы).
D — последний, самый маленький.
